What it shows

Run History lists each playback session with its sequence, start time, duration and result. Running the same sequence twice creates two entries.

Open Run History

Select the Run History icon in the main window. Coming in version 1.0.9 It is also available under Tools → Run History. If the window is already open, Offisen brings it forward.

Results

ResultMeaning
RunningThe run has not ended yet.
SucceededPlayback reached the end with no playback errors.
Completed with errorsPlayback reached the end, but one or more commands failed along the way.
FailedA blocking problem ended the run before it finished.
StoppedYou or the application stopped the run.
InterruptedThe run had no normal end, for example because Offisen closed during playback.

A sequence that never started, for example because its target was not ready, creates no entry.

Select Details to see available information about the run, such as the diagnostic code, correlation ID and failed step.

Attached sequences Coming in version 1.0.9

For each attached sequence the run reached, the entry says what happened:

  • Attached sequence “Add note” ran: its window was found.
  • Attached sequence “Add note” was skipped: its window was not found.
  • With repeats: Attached sequence “Add note” ran 2× and was skipped 3× (window not found).

A skip alone is not an error, so a run with a skipped attached sequence can still be Succeeded. If you expected it to run, check that the window was open and that its title matched the condition. An attached sequence the run did not reach is not listed.

Retry

Retry starts the sequence again as a new run, from the beginning, and adds a new entry. It does not continue the failed run or change its entry. Retry last failed does the same for the most recent failed run only, never an older one.

Retry is available only if all of these are true:

  • The run is Failed and is marked Retryable.
  • The sequence file can still be identified.
  • Nothing is being recorded or played.

Retryable means only that the problem may be fixable; it does not confirm that a new run is safe. Earlier steps of the failed run may already have typed text, saved data or confirmed a dialog, and a new run performs them again. Before selecting Retry:

  1. Check the target application.
  2. Correct what the failed run already changed, if necessary.
  3. Return the application to the state where the sequence starts.
  4. Fix the cause described by the diagnostic code.
