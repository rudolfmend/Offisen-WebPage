Attached sequences with a condition

Add optional steps that run only when their window is open.

What it does

An attached sequence is a saved copy of another sequence, placed inside the sequence you are editing. When playback reaches it, Offisen checks whether its window is open. If it is, the copy runs. If not, the copy is skipped and the run continues.

Example

  1. The main sequence fills in a form in your accounting application.
  2. An attached sequence adds a note in a second application. It runs only if that application's window is open, and is skipped otherwise.
  3. The main sequence continues in the accounting application and selects Save.

Attach a sequence

  1. Open the Sequence Editor.
  2. Select Attach sequence on a card, or Attach sequence at the start above the steps.
  3. Choose a saved sequence.
  4. Under Which window meets the condition, choose an option and read the condition shown.
  5. Select Apply, then save the sequence.

A card appears with a caption such as Attached sequence “Add note” – plays only if the window “Notes” is open. Its first and last steps are shown as Window check and End of the attached sequence.

The steps are copied. Later changes to the original do not change the copy, and deleting the original does not remove it. The playback settings of the original are not used; the settings of the main sequence apply.

Which window meets the condition

Choose Only the window with exactly this title when the title identifies the right window. It is the default. Choose Any window of the same application when the title changes, for example with the open document.

Open windowsOnly the window with exactly this titleAny window of the same application
No matching windowSkipped. A window with a different title does not match.Skipped.
One matching windowRuns.Runs, whatever the title.
Several windowsStops with OFS-1806 if several match equally well.The recorded title decides. If none or several of them have it, stops with OFS-1806.

Offisen never guesses between windows and does not choose the most recently used one.

How the check works

  • One check, no waiting. Offisen checks once when playback reaches the copy. It does not wait for the window to open, so add a wait before the copy if the window needs time.
  • Every repeat checks again. When the main sequence repeats, the copy can run in one repeat and be skipped in another.
  • The start is not affected. The copy's windows are not checked before the run starts, also with Run only if target is ready.
  • A window is not the same as ready. The condition confirms that the window is there. It does not confirm that buttons or fields inside it are ready. The copy's steps go through the usual playback checks.
  • Other windows are not part of the condition. When the editor says that steps look for their window on their own, those steps find their window when they run. If that fails, the run can stop.

Run, skip or stop

SituationResult
The window is foundThe copy runs, then the main sequence continues.
The window is not openThe copy is skipped and the main sequence continues. This is not an error. Run History records it.
Several windows fit and none can be chosenThe whole run stops with OFS-1806.
The check itself fails, or the window changes while it is being confirmedThe whole run stops with OFS-1809. This does not prove that the window is missing.
The window closes or changes after the copy has startedThe whole run stops with OFS-1809. The rest of the copy is not skipped, and nothing is typed elsewhere.
An ordinary command in the copy failsThe Stop sequence when a command fails setting of the main sequence decides.

These safety stops end the run even when Stop sequence when a command fails is off. Stopping playback yourself also ends the whole run. Keep the copy's window open until the run finishes.

Change a copy

ChangeHow it works
Text and waitsEdit text and Edit wait work on steps inside the copy. No other step inside it can be changed, inserted or removed.
ConditionChange condition changes only the condition and works without the original. If the window has no application name, only its exact title can be checked.
DeleteDelete removes the whole copy.
MoveMove up and Move down move the whole copy. In a sequence with parts, the copy is its own part and does not move.
UpdateUpdate from original replaces the copy with the current steps of the saved sequence. Changes made to the copy, such as texts and waits, are lost. It is offered only if a saved file with the original's name exists.

Each of these changes is one Undo step and takes effect when you save. Steps after an attached copy get new numbers, so their target check exceptions end. See What saving changes.

Limits

  • One level only: a sequence that already contains an attached sequence cannot be attached.
  • Text insertion: only a sequence that inserts text as recorded can be attached, and the copy always plays that way. The main sequence can still use the current cursor. See Text insertion after an attached sequence.
  • No application launch: a sequence with a step that starts an application cannot be attached.
  • A window to check: the sequence needs a step in a window with a title.
  • Merging: a sequence containing an attached sequence cannot be merged.
  • Parts: in a sequence with parts, the copy becomes its own part and new steps cannot be inserted into it.

Using the file in other versions

A sequence with an attached copy is saved in a newer file format. Offisen 1.0.8.0 and earlier do not list that file, do not play it and do not change it. Keep this in mind when you share the file with someone on an older version, or return to one yourself.

Sequences without an attached copy keep their existing format.
