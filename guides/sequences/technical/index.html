Purpose and verified scope

A saved .acseq file preserves a sequence for later playback. Its target information allows Offisen to look for a currently running window when the original window no longer exists.

Recorded manual validation with TestBench Target covered loading a saved sequence, closing and reopening the target application, rediscovering its new window and successfully replaying a recorded click. A client-area coordinate fallback was also verified after a target restart.

Interpret the restart evidence precisely

The documented test covers restarting the target application. Reuse on the same PC after an application or Windows restart is a supported design requirement; a separate full Windows restart test and a different-PC test are not established by this validation.

What is saved — and what is live

Main sequence data and runtime state
Area Saved behaviour and practical meaning
Sequence content The name, description and ordered command list. Commands carry their type, recorded values, text or key data and applicable parameters. Only the last successfully saved state is available on reload.
Window identity TargetWindowIdentity contains the process name, window title and Win32 window class. These describe the target; they are not a persistent reference to a running window.
Element information Available recorded control information, such as automation ID, name, class and control type. Presence and strength vary with the target application and the captured control.
Geometry Captured element-relative information and, where available, client-area-relative coordinates, client dimensions and window DPI. Stored geometry does not guarantee that the same control will occupy that position later.
Text-cursor mode CurrentTextCursorMode is saved with the sequence. The mode is persistent; the current caret position and its live destination are not a saved application session.
Runtime window handle WindowHandle and WindowHandleValue are excluded from the saved command data. A loaded command starts without a live handle. A process ID is not part of the persisted target identity.
Whole-run repeats The finite repeat count and infinite-playback flag are held in memory. A new Offisen process starts at 1 repeat, infinite off. These are separate from repeat parameters stored on individual commands.

Saving a sequence does not save the target document, open tabs, sign-in state or the application’s current view. Prepare those separately before reuse.

How the target is found again

Window selection

In the ordinary recorded-target path, a known process name restricts the candidate windows. Exact normalised title matches take precedence over substring matches. The recorded Win32 class can narrow a tie; it is not a mandatory filter that rejects an otherwise unique title-and-process match.

When several windows remain plausible, additional element evidence may distinguish them. If a unique target cannot be established, playback is blocked with OFS-1806. Merely bringing one of two indistinguishable windows to the foreground is not a reliable way to resolve this ambiguity.

Control and pointer resolution

Finding a window and finding the intended control are separate decisions. A sufficiently matched live control provides a stronger anchor than window geometry alone. When live element resolution is unavailable, a recorded client-area-relative fallback may be usable if the required metadata and current geometry pass the safety checks.

The fallback is anchored to the window’s client area, excluding its title bar and borders. It does not establish that the same button, content or responsive-layout position is present. Unsafe or unavailable coordinate conversion blocks the affected pointer command with OFS-1402.

The same DPI value does not prove compatible geometry

A window can be found and activated correctly while its recorded click still cannot be replayed safely. A materially different width-to-height scaling ratio can cause OFS-1402 even when the captured and current DPI are identical.

Text entry and launch settings

Saved text-cursor modes
Mode Text-entry behaviour
Recorded Uses the recorded targeting and caret-placement behaviour. This is the default for a new sequence.
AtStart Only the first qualifying text-entry cluster uses the current live caret target. Later clusters use their recorded targeting.
Always Each qualifying text-entry cluster uses the current live caret target.

Current-caret modes are deliberate targeting overrides. Prepare the intended editable destination before playback; do not interpret the saved mode as restoration of an old cursor location.

Whole-run repeat options are captured at the start of a new playback run. Changing them after that affects a subsequent launch. Check the displayed repeat count and infinite option before each validation run.

A repeatable operating procedure

  1. Establish a known starting state

    Open the required application, document, sheet and view. Record any important layout or display assumptions. Use one unambiguous target where possible.

  2. Record, inspect and save

    Review the command order, payloads and cursor mode. Use Save All and confirm successful saving. Retain the working .acseq before making further changes.

  3. Restart and reload deliberately

    Close and reopen the components being tested, then prepare the target state again. Select the saved sequence or load its file through Open. State explicitly whether the test restarted the target app, Offisen or Windows.

  4. Run once and inspect the outcome

    Set one repeat and disable infinite playback. Press Play. Confirm the actual application result, including the intended document and control, rather than relying only on completion status.

  5. Stop, diagnose and restore before retrying

    If a step fails or targets the wrong place, use Stop. Capture the failing step and diagnostic reason. Inspect changes already made and restore the starting state before another run.

Troubleshooting and recovery

Common failures during saved-sequence reuse
Symptom Checks and next action
File missing or unreadable Check the actual file path, access, non-zero file size and sync availability. Use a working copy or re-record if the file is damaged or incompatible.
Window or control not found Confirm the application is open and ready. Compare the document title, interface language, required dialog and control availability with the recording.
OFS-1806
Ambiguous target		 Inspect the number of matching windows. Save work and close unnecessary copies. Identical process names, titles and window classes may still be indistinguishable without stronger element evidence.
OFS-1402
Unsafe coordinate conversion		 Inspect the failure reason and captured/current client geometry, DPI and monitor setup. Restore compatible window proportions or re-record in the intended layout. Do not assume that any OFS-1402 means the DPI values differ.
Wrong text destination or content Stop playback. Check cursor mode, editable focus, active document, sheet/tab and scroll position. Window identity alone does not prove the intended content state.
Intermittent success after retry Check target readiness and the recorded diagnostic evidence. A later success does not establish the root cause of the first failure. Restore the starting state before repeating the workflow.

Limits of reuse and portability

  • Application changes: titles, languages, control identifiers, layout, dialogs and content can change. Revalidate after changes to the target environment.
  • Ambiguous or weak targets: identical windows, controls with little identifying information and transient or title-less popups can limit rediscovery.
  • Coordinate fallback: compatible geometry is weaker evidence than a resolved control. Scrolling, content changes or rearranged toolbars can alter what occupies the same position.
  • Different computers: the identity model supports rediscovery, but a successful restart test on one PC does not establish compatibility on another. Test the intended applications and display configuration independently.
  • Historical files: compatibility with recordings from older identity and geometry schemas is not guaranteed. Use a current recording when an old file cannot be reused reliably.
  • Partial execution: do not assume that stopping or blocking playback undoes earlier actions or that a fresh launch resumes at the failed step. Inspect the target state before retrying.

Information to collect for support

Record the Offisen and target-application versions, the sequence step, exact error code and failure reason, available diagnostic output, number of matching windows and relevant display or layout changes. Specify what was restarted and whether the problem reproduces from the same starting state.

Contact info@offisen.app. Inspect recorded text and values before sharing an .acseq file.
