OFS-1804

Unable to safely click inside a popup or flyout

Offisen could not safely re-identify the exact control inside a transient popup or flyout, so no mouse button input was sent.

What this means

Menus, flyouts, and popup surfaces can disappear and be recreated with different contents. When the original control cannot be confirmed, a raw position click could select the wrong item, so Offisen blocks it.

What to do

  1. Open the popup, menu, or flyout manually.
  2. Make sure its contents and ordering match the state used during recording.
  3. Retry playback.
  4. If the application interface changed, record again the step that opens and uses this popup.

Why this can happen

  • The popup was closed or had not opened yet.
  • The popup contents, order, or structure changed.
  • The recorded control could not be resolved to a live element.
  • The application recreated the popup as a transient auxiliary window.

Example

A context menu now contains a new item, shifting the recorded option. Because Offisen cannot confirm the original menu item, it does not fall back to clicking the old screen position.

If the problem continues

If the popup visibly matches the recording but remains unresolved, copy the report and identify the application and type of popup. The report does not include the popup item text.

Include the error code, correlation ID, timestamp, Offisen version, target application when relevant, and a short description of what happened. Review the report before sharing it and remove anything you do not want to send.
