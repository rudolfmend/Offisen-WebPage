OFS-1105

Key press may have taken effect

A key press may have been sent completely or only in part. Offisen sent a release for all of its keys, did not repeat the key press and stopped playback.

What this means

While playing a key or a shortcut such as Ctrl+V or Enter, something went wrong after input may already have reached Windows. The key press may have taken effect in the target application, or it may not have.

Offisen sent a release for every key of the shortcut. That does not mean nothing happened: the key press itself may still have taken effect.

Offisen does not repeat the key press, because repeating it could paste, confirm or delete a second time. Playback stops even when Stop sequence when a command fails is turned off.

What to do

  1. Do not run the sequence again yet. Earlier steps and this key press may already have taken effect, and a new run would perform them again.
  2. Check the result in the target application. For example, text may already be pasted, or a dialog may already be confirmed.
  3. Correct the target application if needed. Run playback again only when the sequence can safely start from that state.

Why this can happen

  • Windows accepted only part of the key press.
  • The request to send the key press ended without a clear result.
  • The whole key press was sent, but the command was still reported as failed.

Example

A sequence presses Enter in a confirmation dialog and the code appears. The dialog may already be confirmed. If you ran the sequence again without checking, the next run could confirm something else or start the same work twice.

How this differs from OFS-1104

Both codes mean that a key press may have taken effect and was not repeated. Offisen reports OFS-1105 when it sent a release for all of the keys. It reports OFS-1104 when the release of all keys could not be confirmed, so a key may still be held down.

Diagnostic details

“Sent” means that Windows placed every release event in its input stream. Windows does not report whether the target application received or acted on them, so this code never confirms what happened in that application.

If the problem continues

Check whether security tools, remote-desktop software or other software that intercepts input is filtering simulated keys. Also check whether the target application runs with higher permissions than Offisen; see OFS-1001.

Include the error code, correlation ID, timestamp, Offisen version, target application when relevant, and a short description of what happened. Review the report before sharing it and remove anything you do not want to send.
